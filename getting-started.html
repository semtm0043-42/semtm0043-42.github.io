01
Hardware orientation · robot and controller

Meet the 3Pi+ and StampC3

10–15 min

Your physical system combines a Pololu 3Pi+ 32U4 mobile robot with an M5Stack StampC3 controller. Inspect the system to identify the parts that sense, move, and communicate.

For this coursework, you will program the StampC3 controller. The Pololu 3Pi+ runs supplied middleware that operates its motors and sensors; the StampC3 requests sensor information and sends motor commands.

02
Development environment · hardware

Install and Configure the Arduino IDE

20–30 min

We will use the Arduino framework to program the StampC3. Arduino IDE is the core editor, compiler, and upload tool for the supplied robot program.

Setup checklist

  1. Install Arduino IDE.
  2. In Preferences, add M5Stack's Board Manager URL: https://static-cdn.m5stack.com/resource/arduino/package_m5stack_index.json.
  3. In Board Manager, install the M5Stack board package.
  4. Select Tools → Board → M5Stack Arduino → M5StampC3.
  5. Set Tools → USB-CDC On Boot → Disabled.
Check M5StampC3 is selectedSet USB-CDC On BootKeep setup errors
03
Physical robot · recoverable baseline

Prepare a Copy of the StampC3 Template

10–15 min

Your supplied local course workspace contains StampC3_Template, DigitalTwin, and investigations. Preserve the supplied template as a known-working recovery point before changing code.

Workspace checklist

  1. Copy the complete StampC3_Template folder to a working location.
  2. Rename the copied folder and its main .ino file to the same meaningful name, such as Test1.
  3. Open the copied .ino file in Arduino IDE.
  4. Edit myAP to a unique access-point name and set myPassword to a dedicated password that you do not reuse for an account, application, or service.
Copy the complete templateRename folder and .ino togetherKeep the original unchanged
04
Physical robot · known baseline

Edit, Compile and Upload to the StampC3

20–30 min

Confirm that the supplied system works before modifying its behaviour. Use Arduino IDE to compile and upload the copied sketch you prepared in Exercise 3.

Run checklist

  1. Connect the StampC3 by USB and select its serial port in Arduino IDE.
  2. Verify that M5StampC3 is selected as the board.
  3. Use Verify to compile your copied sketch.
  4. Use Upload to program the StampC3.
  5. Open Serial Monitor at 115200 baud and record the first visible output or complete error message.
Edit your copied sketchCompile in Arduino IDERecord the upload result
05
Simulation environment · visual model

Install and Configure Processing IDE

10–20 min

Processing runs the supplied Digital Twin on your computer. It is separate from Arduino IDE, which edits and uploads the StampC3 controller.

Setup checklist

  1. Install Processing 4.
  2. Open Processing once and confirm the editor starts in Java mode.
  3. Open the supplied Digital Twin sketch from the DigitalTwin folder in your local course workspace.
Check Processing opensIdentify Run and consoleKeep launch errors
06
Common baseline · physical and simulated run

Run the Digital Twin Demonstration

30–40 min

Run the supplied physical and simulated examples as parallel systems. The Digital Twin computes its own behaviour; it is not a display of robot telemetry. Observe both systems before changing their code or constants.

Run and observation checklist

  1. Open your copied StampC3 sketch in Arduino IDE, compile it, and upload it.
  2. Open the Processing sketch in DigitalTwin and run it.
  3. Start the physical robot as directed and confirm both systems begin from the supplied baseline.
  4. Describe both paths without explaining them yet.
  5. Identify one agreement and one disagreement. State separately what you observed and what you inferred.
  6. Choose one question that could be investigated by measuring motors, surface reflectance, or odometry on the real robot.
Run physical and simulated examplesSeparate observation from explanationPose one testable question
07
Telemetry · direct connection

Take Measurements with Serial

10–15 min

The StampC3 provides direct Serial information. Before interpreting a value, identify what it represents and when it was measured.

Measurement checklist

  1. Use Serial Monitor to identify a timestamp and one changing value.
  2. Record a field name, units or range if known, timestamp, and whether it is a command, sensor reading, encoder count, or pose estimate.
  3. Keep the first relevant error message if the output does not appear.
Serial inspect a direct recordInterpret field, time, and sourceKeep an error if needed
08
Telemetry · optional live comparison

Observe WiFi Telemetry

10–15 min

The supplied WiFi server lets the Digital Twin receive telemetry from the robot. This changes the transport, not the need to understand the source and timing of each value.

Measurement checklist

  1. Start the supplied WiFi/TCP server and simulator.
  2. Identify one telemetry record received by the Digital Twin.
  3. Compare its timestamp and fields with the Serial information you inspected.
WiFi confirm a TCP recordCompare transport and timingInterpret field and source
