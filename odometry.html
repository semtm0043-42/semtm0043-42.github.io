CW2026/Phase 1/Odometry
Real robot investigation

Discover the robot’s
geometry through motion.

Odometry estimates position and heading from wheel encoder motion. Encoder counts are direct measurements of wheel rotation: use independent physical observations to determine how those counts become distance and turn, then check a simple Euler pose model against a new observation.

How to use this page

Build one transparent chain of evidence

Each exercise contributes one part of an odometry investigation: a trustworthy observation, an identifiable parameter, a calculation, or a check. Keep its data, plots, notes, and code under investigations/phase-1/student-3-odometry/, and save checkpoint snapshots in the corresponding investigations/checkpoints/checkpoint-N/student-3-odometry/ folder. Core investigation sequence

From encoder readings to a checked pose prediction

Use the same record throughout: requested motion, encoder changes, independent measurements, uncertainty, and what the model predicted.

01
Orientation · interface

Reading encoder data from the StampC3

20–25 min

Trace the data that you will trust. In Robot.h, getEncoders() requests a new cached RobotEncoders_t snapshot. getLeftEncoderCount() and getRightEncoderCount() give named access to it. A value remains cached until you request another snapshot.

Investigation brief

  1. Locate getEncoders(), encoders, last_encoders, and the named getters in the template and system reference.
  2. Make a short program that requests counts at known intervals and prints left and right values.
  3. Record which physical wheel and array channel correspond to left and right.
Reason it out

What difference would you expect between a cached reading and a live hardware register? Decide when your routine needs a new request.

AI-assisted option

Ask AI to explain the code path in your own words, then verify every claimed data member and method in the source.

The source code is the API contract.

02
Orientation · measurement

Establishing an independent physical reference

20–30 min

Encoder counts cannot independently tell you whether the robot travelled the intended distance or angle. Define a taped distance scale and start line for translation, plus a marked heading line, large protractor, or overhead image for rotation. State the robot point that represents pose and how accurately the reference can be read.

Investigation brief

  1. Choose a reference point on the robot and draw its coordinate frame, positive heading direction, and start alignment.
  2. Prepare a distance and heading reference which does not use robot.pose.
  3. Make one short trial and record the reference before and after motion, including likely reading uncertainty.
Reason it out

Identify one alignment or parallax error in your apparatus and decide how you will detect or reduce it.

AI-assisted option

Ask AI to critique a sketch of the reference method and list possible confounds. Retain only suggestions you can inspect physically.

The reference must remain independent of the model.

03
Data collection · timing

Building an encoder logging routine

25–35 min

Odometry is a sequence of encoder updates, not only a start and end calculation. Build a small routine that records a StampC3 time, both encoder counts, and a motion label at a consistent interval. This record will later let you replay the model and inspect individual updates.

Investigation brief

  1. Log robot.getMillis(), left count, right count, and a trial identifier over one short motion.
  2. Inspect the intervals between rows and explain any variation.
  3. Keep a raw, unmodified version of the log alongside any processed table or plot.
Reason it out

Choose a logging interval that reveals encoder changes without creating unnecessary duplicate rows. Explain the trade-off.

AI-assisted option

Ask AI to help parse your CSV and plot counts against time, but check row count, units, and timestamps against the raw file.

Keep raw observations separate from processing.

04
Data quality · conventions

Checking encoder signs and repeatability

25–35 min

Before fitting geometry, establish how count changes relate to forward, reverse, and rotational motion. Repeated nominal motions also reveal whether counts and physical outcomes are stable enough for the proposed calibration. The question is not whether every trial is identical, but whether variation is visible and recorded.

Investigation brief

  1. Use short forward, reverse, left-turn, and right-turn trials; record count signs and physical direction.
  2. Repeat one nominal motion several times and compare count changes and the independent final reference.
  3. Note any slip, start alignment, battery, or surface effects that limit interpretation.
Reason it out

Make a sign table before calculating any distance. Which observation would show that your convention has been applied inconsistently?

AI-assisted option

Ask AI for a compact repeatability summary or plot, then inspect the individual trials it labels as unusual.

Do not discard a trial without recording why.

05
Translation · calibration

Estimating wheel distance per encoder count

35–45 min

For each wheel, encoder-count change becomes a distance through a scale such as millimetres per count. Begin with nominally straight motion because it provides a clear physical distance reference. The helper can make repeatable starts, but physical distance and encoder changes are still measurements to fit.

Investigation brief

  1. Use startMoveDistance(...) to request at least two nominal travel distances and record counts before and after each run.
  2. Measure forward travel independently and fit a transparent distance-per-count estimate with units.
  3. Use one repeat or distance as an initial check rather than fitting every row.
Reason it out

Decide whether a graph, ratio, or fitted line makes the scale and its uncertainty most visible. State why.

AI-assisted option

Ask AI to calculate a candidate fit and residuals from your table. Reproduce the calculation and retain its equation and units.

A fitted value needs its raw measurements.

06
Translation · asymmetry

Testing left and right wheel scales

30–40 min

A shared scale is a useful first approximation, but equal nominal encoder travel can still produce a shallow curve. Use lateral displacement, final heading, and the two count changes to ask whether the measurements support separate left/right distance scales or whether the variation is too large to justify that extra complexity.

Investigation brief

  1. Repeat straight trials in both directions where practical and measure final lateral displacement or heading.
  2. Compare left and right count-distance relationships and residual patterns from the shared-scale model.
  3. State whether a separate-scale model is supported, and what observation could distinguish scale mismatch from alignment error.
Reason it out

What residual pattern would make a shared scale doubtful? What pattern would instead suggest an inconsistent start alignment?

AI-assisted option

Ask AI to compare shared and separate-scale fits using your data, then examine whether the apparent improvement exceeds your reference uncertainty.

Prefer the simplest model the measurements support.

07
Rotation · observation

Relating differential wheel travel to heading

25–35 min

Heading change arises from the difference between right and left wheel distances. Before estimating a geometric parameter, use recorded turn trials to check that the sign and relative size of the observed heading change agree with the wheel-distance difference calculated from your current scale.

Investigation brief

  1. Use startRotateAngle(...) for several nominal turns in both directions.
  2. Record encoder changes and independently measured final headings.
  3. Make a signed comparison between sR − sL and heading change; identify any convention error before fitting separation.
Reason it out

Predict the sign of the heading change before the trial. What would a reversed sign imply about your code or coordinate frame?

AI-assisted option

Ask AI to check a hand-worked sign example, then reproduce the calculation using one of your own recorded rows.

Use physical heading to check the algebra.

08
Rotation · geometry

Estimating effective wheel separation

35–45 min

With wheel-distance scale established, estimate the effective wheel separation B from Δθ = (sR − sL) / B. This initial experiment supports one effective separation, not separate left/right centre-to-wheel values. Keep the first model as simple as the evidence allows.

Investigation brief

  1. Use the recorded heading trials to calculate an effective separation for several turn magnitudes and directions.
  2. Compare estimates and state a central value and plausible uncertainty or range.
  3. Explain how error in wheel scale or physical heading measurement affects this estimate.
Reason it out

What happens to the estimated separation when the measured heading is too small? Explain from the equation, including units.

AI-assisted option

Ask AI to check unit conversion and sensitivity in your calculation. Compare its explanation against a hand-worked example.

A plausible equation still needs measured heading.

09
Model · hand check

Working through one Euler pose update

25–35 min

Before processing a full log, work through one encoder interval by hand. Convert count changes to wheel distances, calculate forward distance and heading change, then apply the supplied first-order Euler update. This exposes units, signs, and reference-frame choices that can be hidden in a program.

Investigation brief

  1. Select one consecutive pair of rows from a turn log.
  2. Calculate Δcount, sL, sR, forward distance, heading change, and the updated pose.
  3. Compare the hand result with a one-step implementation using the identical input.
Reason it out

Choose values simple enough to calculate independently. Which unit or sign error would be most visible in this one-step check?

AI-assisted option

Ask AI to check your shown arithmetic, not to invent values. Verify every intermediate number with a calculator or independent script.

A hand check anchors the implementation.
Focusone updateEvidenceworked calculationCheckcode matches maths
10
Model · replay

Replaying an encoder log through the Euler model

35–45 min

Use the calibrated distance scale and effective separation to replay a complete recorded trial. Plot the predicted pose sequence or at least its final position and heading against the independent reference. Begin with a trial used for calibration only to check that the implementation behaves as intended.

Investigation brief

  1. Enter the current parameter values, units, and coordinate convention into the supplied Euler model.
  2. Replay one straight and one rotation log, plotting or tabulating predicted and measured final pose.
  3. Check whether a different logging or integration interval materially changes the result.
Reason it out

Separate a code check from a physical validation. Which already-used trial is useful for debugging but not for a final prediction claim?

AI-assisted option

Ask AI to help construct a reproducible plot from your log and parameter file. Check that the plotted trial identifier is correct.

Calibration data cannot also be the sole validation.

11
Evaluation · uncertainty

Analysing residuals and uncertainty

25–35 min

A residual is the difference between model prediction and independent observation. Examine its direction, size, and repeatability before revising parameters. Consistent residuals can suggest scale, separation, or convention issues; scatter can arise from slip, floor effects, start alignment, or reference uncertainty.

Investigation brief

  1. Calculate position and heading residuals for repeated calibration trials.
  2. Compare the residual size with the variation in your reference measurements.
  3. Write one testable explanation and one next experiment that would distinguish it from an alternative.
Reason it out

Classify one residual pattern as potentially systematic or non-systematic, then name the observation needed to support that classification.

AI-assisted option

Ask AI to propose competing explanations for your residual plot. Reject any explanation that does not identify a discriminating measurement.

Residuals guide the next observation.
Focuserror patternEvidenceresiduals + repeatsDecidenext experiment
12
Prediction · validation

Predicting a held-out motion

30–40 min

Reserve one straight or rotation trial that was not used to choose parameters. Before running it, state the requested motion, predicted final position and heading, and expected uncertainty. Then collect the independent reference and explain the difference without silently refitting the model.

Investigation brief

  1. Freeze the parameter values and choose a new motion within the safe range of your apparatus.
  2. Record a dated prediction before observing the final physical reference.
  3. Compare prediction and observation, then state what the result supports, limits, or leaves uncertain.
Reason it out

Choose a held-out motion which is informative but does not introduce an entirely untested behaviour. Define success before running it.

AI-assisted option

Ask AI to format your prediction table or plot template before data collection. Do not provide the final observation until the prediction is recorded.

Prediction precedes observation.

+
Optional investigations

Going Further with odometry

Use these extensions after the core Euler model has been calibrated and checked. Select one because it answers a question raised by your residuals, not simply because it creates a more complicated path.

01

Curves and asymmetric geometry

Use left- and right-turning arcs to test whether separate left/right centre-to-wheel separations explain a repeatable residual better than one effective separation.

02

Exact differential-drive integration

Implement exact constant-curvature integration and compare it with Euler using the same encoder log. Decide whether the difference is meaningful relative to reference uncertainty.

03

Bidirectional square benchmark

Run repeatable clockwise and counter-clockwise squares to expose accumulated systematic error. Use this as a diagnostic, not as the first place to fit every parameter.

Before Phase 2

Carry a transparent model forward

Keep raw encoder records, the physical reference method, fitted values, calculations, residuals, and held-out prediction together. They provide the basis for deciding what the Digital Twin represents well and what it should improve.
