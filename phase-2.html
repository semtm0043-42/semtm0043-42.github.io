Simulation environment · visual model

Install and Configure Processing IDE

10–20 min

Processing runs the supplied Digital Twin on your computer. Processing is a very convenient tool to generate graphical outputs that requires minimal setup and configuration. The provided Processing code has been written to provide:

  1. A simple simulation model of the robot. This simulation can be used independently of the StampC3.
  2. To connect to the StampC3 (your robot) over WiFi. When connected, to visualise the data sent back from your robot
  3. To run the same controller code on both the StampC3 and the simulated robot. This will allow you to compare and investigate differences between the real robot and simulation.
Processing is separate from Arduino IDE, which edits and uploads the StampC3 controller.

Setup checklist

  1. Install Processing 4.
  2. Open the Processing application.
  3. Select File → Open, then navigate to the DigitalTwin directory, then select DigitalTwin.pde. The DigitalTwin directory should have been included in the download or repository provided to you as the StampC3_Template code.
  4. Click the Play icon to run the simulation. You should see a visualisation of a robot following a line.
    1. Pressing the 'g' key will toggle the visibility of the plots.
    2. Pressing the 't' key will toggle between following the robot or not.
    3. Pressing the '-' or '+' key will decrease or increase the zoom respectively.
    4. More guidance on the Digital Twin simulation is provided in the exercises for Phase 2 of this course

02
Common baseline · physical and simulated run

Run the Digital Twin Demonstration

30–40 min

We should now be ready to run the full demonstration of the Digital Twin robotic system. Follow the steps below to verify that the full system works as expected. When the demonstration works correctly, you should see an output from the Processing Digital Twin that looks like the following image:

In the above image, we can observe:

  1. The simulated robot as the blue circle. Black dots represent the sensor placement.
  2. The real robot as the orange circle, without the black dots for sensor placement.
  3. At the top, the status line TCP: Connected to 192.168.4.1:80 indicating the simulator is connected to the real robot over WiFi. The real robot should always have this address.
  4. In the graph panel, multiple sets of data plot concurrently, for both the simulated robot and the real robot.

Run and observation checklist

  1. Place your robot on the provided test map, at the start location indicated with grey markings
  2. Turn on your robot by pressing the small on/off button once. The StampC3 should illuminate the on board LED. Your robot should not yet move.
  3. Connect your computer via WiFi to the robot. The robot should show up in the available WiFi networks with the name you provided in the previous exercise. Wait for your computer to connect. Your operating system may notify you that the internet is not available - this is expected, not an error. This may mean you have an unusual WiFi icon, such as a question mark.
  4. Open the Processing sketch in DigitalTwin and run it. It should immediately start running the simulated controller.
  5. Press the m key once to toggle the simulator mode to live.
  6. Start the physical robot by pressing the button on top once. The real robot should begin following the line.
  7. Verify in the Digital Twin that the visualation for both the real robot and simulated robot are moving.
  8. The visualisation of the real robot and simulated robot will behave differently - this is expected. In fact, these differences represent the core matter of interest for this course.

03
Telemetry · direct connection

Debugging: Take Measurements with Serial

10–15 min

The StampC3 provides information via the Serial port connection. During this course, using the Serial connection is likely to be the most effective way for you to debug your code. Follow the next steps to test your Serial connection.

Measurement checklist

  1. Connect your StampC3 to your computer using a USB-C cable.
  2. Select Tools → Port and select the port for the StampC3.
  3. Select Tools → Serial Monitor. You may need to change the baud rate - use the drop-down list to select 115200.

  4. In the StampC3_Template code, navigate to the Controller.cpp tab, and search for the function named publishTelemetry(...).
    1. The functions server.printf(...) and Serial.printf(...) both report 14 variables. Which aspect of the robot do you think each variable corresponds to?
    2. Both server.printf(...) and Serial.printf(...) has a string formatted like %lu,%.2f,%.2f,%.5f,%d,%d,%ld,%ld,%u,%u,%u,%u,%u,%u. You might think this looks a bit strange - but you can also discover what these mean. Use the internet to search for what each of these formatters means (e.g., %.5f).
Troubleshooting
  1. I get the error Board at XXXXXXXX is not available: Make sure your StampC3 is connected to your computer via a USB-C cable.
  2. I don't see any changing information on the Serial Monitor: Make sure that USB-CDC is disabled, select Tools → USB-CDC On Boot → Disabled. You will need to upload the code again.

04
Telemetry · optional live comparison

Inspect WiFi Telemetry

10–15 min

In an earlier exercise, we ran the full Digital Twin system demonstration. As a part of this, the robot sent data to the Processing simulation over a WiFi connection, allowing for a visualisation of the real robot. This exercise will help you to configure some tools to read this information directly, rather than through the Processing simulation. This may become useful for debugging or recording data. When the robot was sending data to the Processing simulation, it had the exact same format as the output we viewed previously via the Serial Monitor.

Measurement checklist

  1. Place your robot, then turn it on via the On/Off button. You should see the on board LED illuminate. The robot should not move.
  2. On your computer, connect to the robot by selecting the WiFi network with the name you gave earlier.
  3. If you are on MacOS or a Linux Operation System, open a Terminal instance (command line) and issue the following command:
    nc 192.168.4.1 80
    You should see the data from the robot printing to the terminal window. If you want to save this data to a file, you can use the following command:
    nc 192.168.4.1 80 > saved_data.csv
    where saved.csv is your chosen file name. Simply press ctrl+c or cmd+c to end the process.
  4. If you are on a Windows operating system, we recommend you download and install an application called PuTTY. We will use this to create a connection to the robot and view the data output.
    1. Follow the installation instructions here.
    2. Open PuTTY, then configure the connection to look like the below screenshot. Note that you need to set the Host Name to 192.168.4.1, the port to 80, and the connection type to raw. Then click Open.
